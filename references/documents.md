# 資料 (HTML) と引き継ぎ

## HTML にする

Markdown を読めない人は多い。資料は `.md` を元データにして `tools/md2html.py` で HTML を作る (依存ライブラリなし)。
対応書式: 見出し、段落、箇条書き (入れ子)、表 (右寄せ)、コード、太字、リンク (`.md` へのリンクは `.html` に置換)、画像、区切り線。
ダークモード対応の CSS。各ジェネレーターの最後で `md2html.refresh()` を呼べば、データを作り直したときに HTML も更新される。

入口ページ `はじめにお読みください.html` (資料一覧 + 画像カード) も同じスクリプトが作る。`DOCS` と `CARDS` をプロジェクトに合わせて書き換える。

## 製作者向け資料 (他人に製作を頼むとき)

`tools/handover.py` (+ `tools/dump_pcb.py`) が作る。寸法・部品表は回路定義・基板・筐体から自動で引くので、設計を変えたら再実行すればよい。

内容:
1. 製作物の概要 (仕様表 + 完成イメージ)
2. 発注・調達 (発注先ごとの内容とファイル)
3. 手はんだ部品表 (向き・極性、基板からの高さ、購入先) と注意
4. 組立図 (基板データから描画。手はんだ部品を色分け、極性・ピン番号を赤字、測定点 TP を赤丸)
5. 寸法 (基板・筐体・パネル穴の表 + パネル図)
6. 配線 (パネル部品と基板コネクタの対応表、線の長さ)
7. 組み込み手順、ねじ・小物の一覧
8. 検査手順 (測定点と期待値)
9. 実物で確認が必要な項目 (確定できなかった点と、合わない場合の対応)
10. 使い方、同梱ファイルの説明

最後に `<プロジェクト>_製作データ.zip` (資料・発注データ・KiCad・筐体・回路図) を作る。メーカーの STEP など再配布できないファイルは入れない。

ユーザーに渡すときは、想定読者 (製作者) を 1行で示し、「誰が発注するか」「実物確認の連絡先」を決めておくよう伝える。

## 原寸チェックと設計の根拠

- 原寸チェック (`tools/print_check.py`): kicad-cli で Edge.Cuts・F.Fab・F.Courtyard・F.Mask・F.Silkscreen を `--scale 1 --black-and-white` で
  A4 に出す。基板の一時コピーに 50mm の目盛りと注意書き (Dwgs.User 層。`User.Drawings` は層名として通らないことがある) を足してから出力する。
  表題欄 (`--include-border-title`) は目盛りの文字と重なるので付けない。PDF の MediaBox が A4 (841.9×595.3pt) で、基板幅が実寸かを確かめる。
- 設計の根拠 (`tools/design_notes.py`): 「項目 / 計算式 / 計算値 / シミュレーション」の表を基本にする。抵抗の組み合わせを間違えやすい
  (例: DC カットの計算に直列抵抗ではなくブリーダーを入れてしまう) ので、式の部品番号を回路図で確かめる。
