# ngspice シミュレーション

## 仕組み

- `tools/sim/build.py` が `PARTS` から ngspice ネットリストを作る。シンボルごとに SPICE 素子へ対応付け、コネクタは試験用の部品に置き換える
  (DC ジャック → 電源、マイク入力 → マイクの等価モデル、出力 → 録音機の入力抵抗、スイッチ → 時間で切り替わる SW)。
  新しいシンボルを使うときは `build()` に対応を足す (無いと止まるので気づける)。
- `tools/sim/run_all.py` が試験を実行し、グラフと `シミュレーション/結果.md/.html` を作る。`REUSE=1` で既存の計算結果を再利用して集計だけやり直す。
- numpy / matplotlib が要る (仮想環境の Python で実行)。

## 用意した試験 (雛形)

| 試験 | 内容 | 見るもの |
|---|---|---|
| T1 | スイッチング込みの起動と負荷急変 | 起動時間、行き過ぎ、インダクター電流ピーク (定格と比較)、MOSFET 電圧、負荷急変後の整定 (振動しないか) |
| T2 | 定常リップルとスペクトル | スイッチング周波数、リップル、可聴帯域の成分 (パルススキップの有無) |
| T3 | AC 解析 | 電源ノイズの伝達 (部品の誤差込み)、信号の通過特性 |
| T4 | 電源 ON/OFF の過渡 (理想電源で長時間) | 出力に出る過渡電圧、立ち上がり時間 |
| T5 | 入力電圧の比較 | 消費電流、ゲート電圧の定格超え |
| T6 | 操作スイッチの ON/OFF | 出力の過渡電圧 |

## モデル

- 制御 IC は動作モデルで十分 (UC3843: 発振はクロック源、誤差増幅器は gm + 出力クランプ、電流比較、ラッチ、UVLO)。
- MOSFET は VDMOS、ダイオード・トランジスタはデータシートからの概算パラメーター。電解は容量 + ESR、MLCC は DC バイアスの容量低下を見込む。
- マイクの等価モデルは「電圧が無いと電流を引けない」形 (`tanh` で頭打ち) にする。定電流源にすると起動時に非現実的な負電圧になり計算が破綻する。

## 収束しないとき (実例で効いた対処)

| 症状 | 原因 | 対処 |
|---|---|---|
| `Timestep too small` / `trouble with node` | 電解モデルの ESL (10nH) | ESL を入れない |
| 同上 (特定ノード) | 電解モデルの内部ノードの位置 | ESR をコンデンサの P 側に置く (`R P a; C a N`) |
| 同上 (B 電源の分岐) | 理想ダイオードの N を極端に小さくした | 通常のダイオード (N=1) でクランプ |
| 同じ時刻で何度も止まる | XSPICE のデジタルラッチとアナログの連携 | ラッチをアナログ等価 (G 源 + C) に置き換え、比較器・UVLO は `tanh` で滑らかに |
| 極端に遅い | `method=gear` | 使わない (trap で十分) |

- 立ち上がりの遅い回路 (1秒級の時定数) とスイッチングを同時に長時間計算しない。スイッチング (数十 ms) と、理想電源での長時間 (数秒) に分ける。
- 定常リップルは「出力を予備充電しておき、少し後でスイッチを開く」と早く定常に入る。積分の時定数が長い帰還ではゆっくりした整定が残るので、
  スペクトルを取る前に 2次式で傾きを除く (除かないと低周波成分と誤認する)。
- 下流 (+48V やマイク出力) の nV 級の値は過渡解析の数値誤差に埋もれる。上流のスペクトル × AC 解析の伝達関数で求める。

## 報告するときの注意

モデルは概算で、基板の配線インダクタンス (ドレインのリンギング) は入っていないこと、極めて小さい値はモデルに強く依存することを添える。
